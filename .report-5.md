# Issue #5 — Daemon foundation: report

Branch `issue-5-daemon`, based on `origin/staging` @ b15cfbf8. Public-safe:

Refs #5. The workflow engine (#6), adapters (#7), and lifecycle (#9) remain
out of scope.

## What shipped

One binary (`herdr-fleet`), no second product binary. New modules:

- `src/dirs.rs` — XDG config/state/runtime/log/backup derivation; private
  dirs created 0700; symlink-leaf refusal.
- `src/lock.rs` — advisory exclusive `flock` daemon lock with pid owner and
  stale-process recovery; Unix socket containment (refuses symlink/other
  sockets, never modifies a foreign socket file).
- `src/state.rs` — SQLite (bundled rusqlite, no system dependency) with
  migration m0001: epoch, grants, idempotency claims, hash-chained audit
  (genesis anchor, prune re-chains the retained window), leases, workflow
  instances, schedules. Claim + audit journaled in ONE transaction before
  any effect; write failures poison the daemon (fail closed). Restart
  reconcile marks interrupted claims ambiguous before any request is served.
  Restore rotation voids resurrected in-flight claims.
- `src/backup.rs` — `VACUUM INTO` snapshot + checksummed manifest;
  restore = copy → fsync → atomic rename.
- `src/daemon.rs` — per-user Unix socket server, newline-delimited
  `hf-rpc-request/v1`; closed method dispatch (13 methods incl.
  `events.subscribe`), typed refusals, replay/claim engine, bounded event
  hub with snapshot/replay/resnapshot and subscriber disconnect under
  backpressure; allowlisted JSONL daemon log; debug-only crash points
  (`HERDR_FLEET_CRASH_POINT`; release builds ignore it). No network
  listener, no telemetry, no auto-update, no notification integration.
- `src/client.rs` — minimal newline-RPC client (CLI + tests only).
- `src/service.rs` — per-user launchd plist + systemd unit rendering and
  install/status/uninstall plan steps (pure fixtures; nothing activates the
  host service manager).
- `src/formats.rs`/`src/schema.rs` — eight daemon wire families mirrored in
  Rust (15 total), closed RPC set incl. `events.subscribe`, fixture corpus
  discrimination.
- `src/commands.rs`/`src/main.rs` — `daemon run|status`, `service
  doctor|install-plan|status-plan|uninstall-plan`; doctor reports
  installed-but-not-running as degraded (partial, exit 3) and a clean
  fixture as ok (exit 0). Read-only CLI stays available when the daemon is
  absent with an explicit `daemon.absent` row (AC3).
- `docs/contracts/spec-daemon.md` — closed method set updated with
  `events.subscribe` + subscribe protocol (AC7).
- `scripts/check-contract-fixtures.py` — oracle closed set updated in
  lockstep (machine-verified: 61 manifest expectations held).
- `Cargo.toml`/`Cargo.lock` — rusqlite 0.40 (bundled), fs2, libc only.

## Acceptance-criteria mapping

- AC1 (single writer): `lock.rs`/`daemon.rs` + integration tests
  `second_daemon_is_refused_while_first_runs`,
  `stale_socket_is_reclaimed_on_restart`,
  `symlink_socket_is_refused_and_socket_perms_are_private` (macOS: same
  suite runs on Linux CI hosts for the Linux path).
- AC2 (sole state authority): all mutations flow through the socket RPC
  with journaled claims; nothing else opens the SQLite file for writing.
- AC3 (read-only availability): `daemon status`/`service doctor` report
  `daemon.absent` with exit 1/0 and the read-only core stays usable.
- AC4 (crash boundaries): debug crash points `backup.after-intent`,
  `backup.after-snapshot`, `backup.after-manifest`,
  `restore.after-intent`, `restore.after-rename`; tests
  `crash_after_intent_reconciles_ambiguous_and_refuses_replay_until_new_key`
  and `crash_after_manifest_leaves_no_claim_and_new_key_converges` spawn
  the real binary, kill it mid-boundary, restart, and assert reconcile
  precedes retry.
- AC5 (fail closed): `readonly_state_dir_fails_closed_and_poisons_mutations`
  (mutation refused with a typed `state.*` error, subsequent mutations
  refused `state.poisoned`); chain-tamper detection refuses to reopen
  (`state.audit_tampered`).
- AC6 (restore): `spent_claims_replay_and_restore_rotates_epoch` — replays
  return recorded responses without re-dispatch, restore rotates the epoch,
  resurrected claims are voided (never runnable again), a fresh key works
  in the restored epoch, replaying the restore does not rotate twice.
- AC7 (events): subscribe resnapshots future cursors, replays contiguous
  cursors with strictly increasing seqs, and a non-draining subscriber is
  disconnected while mutations keep succeeding (bounded backpressure).
  Event content is redacted by construction; daemon logs carry allowlisted
  fields only (AC8).
- AC9 (service plans): `tests/service_plans.rs` asserts doctor/install/
  status/uninstall plans on fixture XDG homes (rendered unit + steps +
  exit codes); nothing on this host was loaded or started.
  Fixture-host (clean Linux) commands, documented for the reviewer/CI:
  `herdr-fleet service doctor --json`,
  `herdr-fleet service install-plan --json` (write the rendered unit, then
  `systemctl --user daemon-reload && systemctl --user enable --now
  herdr-fleet.service`), crash recovery check via `systemctl --user restart
  herdr-fleet.service` + `service doctor --json` (expect `running`),
  uninstall via `systemctl --user disable --now herdr-fleet.service` +
  remove the unit. The macOS equivalents are documented inside
  `src/service.rs` plan output (`launchctl bootstrap gui/$UID …`).
- AC10 (no network): `tests/no_network_surface.rs` static scan over `src/`
  (no Tcp/Udp listener references, no HTTP client, no telemetry/auto-update
  tokens) + daemon binds `UnixListener` only.

## r1 fix round (reviewer FAIL @ 78008a1) — dispositions

1. Public-tree privacy gate RED → FIXED. All absolute-path literals removed
   from tracked sources (`src/dirs.rs`, `src/service.rs` unit tests now
   derive fixtures from `std::env::temp_dir()`). `check-public-tree.py .`
   exit 0 at the new head; report corrected above.
2. Two-writer hole (AC1) → FIXED. The single-writer lock now binds to the
   STATE directory (`XDG_STATE_HOME/herdr-fleet/daemon.lock`, beside the
   database) instead of the socket directory, so two daemons with different
   `--socket` paths but the same XDG state home cannot both write. New
   tests: `two_daemons_with_different_sockets_but_shared_state_cannot_both_write`
   (second refuses with `daemon.busy`, exit 1; RED under the old socket-
   scoped lock because the second daemon would keep serving) and
   `daemons_with_distinct_state_dirs_coexist` (two state homes → both
   serve). Lock/socket perms, peer assumptions, and stale-process recovery
   tests kept unchanged.
3. Spec/impl protocol divergence (AC7) → FIXED by aligning the
   implementation with the documented protocol. `events.subscribe` now
   reads and echoes the `cursor` param exactly as `spec-daemon.md`
   documents; the client sends `cursor`; the response echoes `cursor`.
   (The r0 implementation used an internal `last_seq` param name that
   disagreed with the doc.) No fixture carries the param, so the fixture
   oracle is unchanged (61/61 held).
