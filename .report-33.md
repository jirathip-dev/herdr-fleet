## What shipped

- `src/adapters.rs` — Pi added to the closed `HarnessKind` set (`pi` kind
  name + parse), `HarnessKind::OFFICIAL` is now four adapters, and
  `official_specs()` carries the Pi metadata row: executable `pi`, actor
  `pi`, declared range minimum == current (0, 85, 1), full closed harness
  capability set. Pi's one-shot prompt row is
  `pi --provider deepseek --model deepseek-chat --print -- <payload>`: the
  provider/model pair is opaque adapter metadata carried as argv flags
  (measured 2026-09-08 example; never persisted, never on a wire), the
  payload stays the FINAL data element, and the trailing `--` is pi's
  documented end-of-options guard so a data-last payload that begins with
  `-` can never be parsed as an option. One additive closed auth marker,
  `no api key found`, turns pi's measured missing-key stderr
  (`No API key found for deepseek.`, exit 1, observed 2026-09-08 with an
  isolated HOME) into a `refusal.credentials` typed refusal — failure-shape
  classification of nonzero exits only. No other code, config schema,
  RPC, dependency, or fixture changed (oracle stays 65).
- `tests/harness_adapters.rs` — the shared fixture loop now drives FOUR
  official kinds (fake `pi` included), so every existing AC2 matrix row
  (success, missing executable, auth, unsupported capability, timeout,
  cancellation/interrupt, malformed output, stale identity, process death,
  plain exit) and the AC1 same-plan-fixture loop run against the pi fake.
  Four pi-specific tests added: missing-provider-key env ->
  `refusal.credentials` (fake emits the real pi measured text),
  hostile-payload-as-data + env-allowlist witness on the pinned pi row
  (secret var UNSET in the child, allowlisted PATH only, no injection
  side effect), absolute-$0 witness (spawned identity is the resolved
  absolute executable), and cwd confinement to the assigned worktree
  (canonicalized comparison, macOS-safe pattern).

## Live smoke evidence (local lane run only; nothing committed)

Driver: a throwaway example (deleted before the final commit) that
exercises the adapter library directly — `start` + one `prompt` through
`execute_op_in_worktree` against the sandboxed real pi v0.85.1 in a
disposable worktree under the OS temp dir. Environment allowlist carried
PATH (sandbox bin dir) + HOME only; `DEEPSEEK_API_KEY` was UNSET in the
lane environment (`KEY_FORWARDED=no` printed by the driver) — pi satisfied
the call from its own harness-side credential configuration, which the
adapter never touches, persists, or wires (the adapter contract's
"credentials live in the harness" boundary).

- Task: canary-equivalent INI parser (`inicfg.py` + `test_inicfg.py`,
  python stdlib `unittest` only), spec: comments (`#`/`;`), blank lines,
  sections, first-`=` split, whitespace trimming, case-sensitive keys,
  string values, duplicate-key last-wins, top-level `''` section, and a
  `ValueError` carrying the 1-based line number; >= 14 assertions.
- Result: prompt `status=succeeded`, exit 0, 23.5 s elapsed; worktree
  contained exactly `inicfg.py` + `test_inicfg.py`.
- Acceptance re-run by the lane: `python3 -m unittest test_inicfg -v` ->
  Ran 18 tests, all OK (18 test methods / 26 assertions covering every
  spec rule; acceptance exit 0).
- Transcript: 1,142 bytes captured to the /tmp smoke log; excerpt (head):
  "Done. Two files delivered in ... - **inicfg.py** - parse(text: str) ->
  dict ... comments (even indented) and blank lines ignored ...". No
  secret-shaped text in the transcript (scanned); no key was ever in argv
  (row is flag-only) or any file.
- Process hygiene: after the driver exited, no pi process remained
  (`pgrep` for the sandbox pi path and for `pi --provider` returned
  nothing) — pi exits cleanly, unlike the Hermes canary that lingered.
- pi version probed: `pi --version` -> `0.85.1` (exit 0).
