# Fix round 92-R1 — the rehearsal must leave zero fixture processes on every exit path

Independent verification of the previous head (`d4891d22ca3cd80166ae1cbd99b9cb20bcce6bc4`) ran the
lane's own artifacts and failed the lane's own assertion:

```
FAIL: rehearsal leaves no fixture process behind — 1 straggler(s)
SELF-TEST SUMMARY result=failed checks=43 passed=42 failed=1 skipped=0
```

Fixed in the artifact; the assertion is kept (never relaxed, skipped or deleted) and is the
proof below. Prior sections of this report are left byte-unchanged; one earlier statement is
superseded and is called out in §R1.6.

## R1.1 Root cause (measured, not guessed)

The old teardown was **pid-based and reachable only through the EXIT trap**:

- `stop_fixture` killed the pid remembered from the fixture's pid file. A fixture started but
  not yet recorded, a second fixture, or a kill that raced the fixture's own `sleep 1` could
  escape it;
- nothing watched the sandbox apart from the fixture itself, so any death while no fixture was
  recorded — including `SIGKILL`, where no trap can run — left a process and/or the sandbox
  behind;
- the sandbox tree had **two** potential removers (a fixture-side cleanup and the rehearsal),
  whose concurrent `rm -rf` could leave a partially-emptied tree.

Deterministic RED witness of the leak class, captured in this lane before the fix (a probe
that `SIGKILL`s the rehearsal mid-run):

```
SIGKILL probe: rehearsal exit= -9
leftover processes: 1
     <sandbox>/host/bin/fixture-supervisor --serve
leftover sandbox dirs: 1
```

Five unprompted self-test runs at the previous head were green, i.e. the verifier hit an
intermittent window — a race, not a deterministic bug — which is why the fix is structural
rather than a single-site patch.

## R1.2 The fix (bounded: the rehearsal, its self-test and the plan text)

1. **Kill by path, not by pid memory.** `fixture_pids_now` scans the process table for
   processes whose command line names *this run's* sandbox root (a fresh `mktemp -d` path, so
   only this run's processes can match) and `stop_sandbox_processes` stops them all: TERM →
   bounded wait → KILL → bounded wait → re-scan, excluding the scanning process itself.
2. **A sandbox reaper, started before any fixture** (`<sandbox>/reaper.sh`). When the
   rehearsal disappears — including `SIGKILL` — it stops every remaining sandbox process and
   removes the sandbox root, retrying and verifying, then exits. It runs in a reaper-only
   window: the mid-run fixture stop spares it, and teardown waits for it to exit on its own.
3. **Fixture parent watchdog.** The fixture identifies its parent by command line (not only by
   pid, so pid reuse cannot keep it alive) and exits the moment the rehearsal is gone.
4. **Signal paths.** `INT`/`TERM`/`HUP` are trapped and re-raised through the exit trap, so
   teardown runs on interrupt too (observed exits 130/143/129).
5. **One remover at a time, tolerant removal.** The fixture no longer removes the tree; the
   rehearsal's teardown retries `rm -rf` and verifies, and the reaper does the same on the
   untrappable path.
6. **Teardown is reported, not assumed.** A final teardown step stops the fixtures (sparing the
   reaper), removes the sandbox, waits for the reaper to exit, and verifies both the process
   table and the tree; the summary line carries
   `… failures=… sandbox=… live_paths_touched=0 fixtures_left=0 sandbox_removed=yes mode=… dry_run_exit=…`
   and a non-zero exit means a verification failed or something survived. Superseding §2 of
   this report: `CUTOVER92_REHEARSAL_KEEP=1` now keeps the sandbox **directory** for
   inspection only — it no longer keeps any process, and it is no longer needed to obtain
   standalone dry-run evidence (see R1.7).
7. **Documented dry-run invocation.** `bash scripts/cutover-92-rehearsal.sh --dry-run-only`
   plants the fixture, runs exactly
   `python3 scripts/cutover-92-dryrun.py --target <sandbox>/host/target.json` (the
   `cutover-target/v1` descriptor the rehearsal plants), prints that command and the dry-run's
   **raw exit**, tears everything down, and exits with the dry-run's own code. The descriptor
   is required: running the dry-run without `--target` is a usage error (exit 2).
8. **The assertion is kept, with a broader scan** (not relaxed): `rehearsal leaves no fixture
   process behind` now scans for rehearsal sandboxes, self-test fixture roots and the fixture
   program, and two new cases prove the untrappable path (`SIGKILL` mid-run → no process and no
   sandbox) and the documented invocation above.

# Fix round 92-R2 — never delete or kill what this run did not create

Independent review of `99e9ea2e93e58fcb1c59715fc5e396f9ebe19699` returned **PASS with
findings**; F1 (destructive behaviour in a script an operator runs) is fixed here because it
blocks the owner-approval hand-off. F1's substance: the refusal path exits 2 *after* `SANDBOX`

## R2.1 Reproduced at the reviewed head

Probe harness `A`–`E` against the reviewed head (before the fix):

```
FAIL: A refused root outside the pattern: operator directory survives byte-for-byte — exit=2, refused=True, exists=False, content_equal=False
FAIL: B refused reuse of an existing sandbox-shaped directory: it survives byte-for-byte — exit=2, refused=True, exists=False, content_equal=False
FAIL: E a process this run did not start (naming the sandbox root) is not killed — rehearsal exit=0, bystander_alive=False
```

Root causes: (1) teardown removed `$SANDBOX` unconditionally once the variable was set, and

## R2.2 The fix (bounded: the rehearsal, its self-test, the plan text)

1. **Ownership proof before any removal.** The run writes `.cutover-92-rehearsal-owned` inside
   the sandbox immediately after creating it; **every** removal — this script's teardown and
   the reaper — requires that marker plus the `SANDBOX_OWNED` flag. Without them, teardown
   prints a NOTE and returns without touching the path (refuse rather than delete when
   ownership cannot be proven).
2. **Refusal paths neutralise the variable.** Every pre-creation refusal empties `SANDBOX`
   first and says so (`… nothing was created or removed`), so the exit trap has nothing to act
   on.
3. **Kills are recorded-pid only.** `stop_our_processes` signals exactly the pids this run
   started (each fixture instance's `$!` and its reaper). A path-naming process it did not
   start is *reported* (`sandbox_naming_pids`, read-only) and never signalled. The reaper does
   the same on the untrappable path: it stops the pid recorded in this run's own pid file,
   then removes the tree only when the ownership marker is present.
4. **The probes are kept as the proof** (`scripts/test-cutover-92.py`, 50 checks total): a
   refused root with content survives byte-for-byte; a refused reuse of an existing
   sandbox-shaped directory survives byte-for-byte; a process this run did not start is not
   killed; the green path still cleans up; the SIGKILL path still leaves no fixture process.
   Two static guards pin the mechanism (ownership marker/flag present; no path-scan kill list).
5. Plan text **§10** now states the rule: nothing this run did not create is ever deleted or
   killed, and only processes this run started are signalled.
