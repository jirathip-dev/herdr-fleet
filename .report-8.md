## What shipped

- `src/mutation.rs` (new) — the control-plane mutation engine (`herdr_fleet::mutation`): every granular step kind maps to one deterministic effect (`execute_step` -> `Effect{status, code, message, result}`), and each effect runs through the shared gates below plus its kind-specific gate. Effects: `worktree_create` (linked worktree from the integration checkout, bounded by the worktrees root), `prompt` (harness start/session via worktree-confined execution, C1), `collect_outcome` (bounded log read-back), `review_evidence` (records durable evidence, AC4), `merge` (fast-forward only, exact read-back), `issue_update` (comment/close; closure requires the instance to sit at the plan's `post_merge_verify` step with passing evidence), `branch_push`/`branch_delete` (feature lanes only, merged-head checks), `pr_update` (forge create/comment; external-contributor and production-origin gates), `cleanup` (dirty/unmerged refusals + salvage audit pair), `publish`/`hosted_check`/`post_merge_verify`/`approve` (canary/approval effects; `approve` records the AC10 first-write approval).
- Shared gates (`revalidate_effect` + kind gates, all before any effect): live epoch vs plan/grant/instance (rotated epoch refuses — grants/instances die with their epoch), grant status/expiry (`refusal.grant.expired`), observed issue revision vs the grant binding, workflow/policy hashes vs grant and pinned instance, paused instances refuse without a fresh resume digest, and the step's required capability must be in both grant and instance caps (AC3; phase is enforced at grant-issuance/routing time — apply revalidates the closed capability set). Merge requires current distinct-exact-head review evidence with all bindings (feature head, integration base, workflow hash, policy hash, verdict, named checks) matching the live refs; a moved integration base refuses with `refusal.evidence.stale` and, even when stale evidence is replayed, the git fast-forward fails closed on the moved ref.
- `src/daemon.rs` — `plan`/`apply` RPC handlers replace the `refusal.plan.unavailable` stub: canonical-plan digest recomputation and content-derived `plan_id` (`refusal.plan.identity` on tamper), full typed-param parsing (plan/grant/instance/observed/topology; missing typed params refuse at parse time and never journal a claim), pre-effect intent journaling, fresh-state revalidation under the lock immediately before the effect, effect execution outside the lock, durable records under the lock, claim resolution, and the post-effect salvage audit pair for cleanup.
- `src/state.rs` — schema v3 via the linear m0003 migration (`m0003_control_plane_evidence_approvals`): durable review-evidence rows (feature head + integration base + workflow/policy hashes + verdict + named checks, per-instance latest with append-only history) and recorded first-real-write approval rows (scope + digest + interaction flag). Grant invalidation on a material issue/acceptance edit (AC2) and epoch-rotation invalidation both invalidate bound running instances (C3: an instance bound to an invalidated grant can never advance).
- `src/schema.rs` — plan `STEP_KINDS` extended (after `publish`): `branch_push`, `pr_update`, `issue_update`, `hosted_check`, `post_merge_verify`, `branch_delete`, `approve`; unknown kinds stay refused.
- `src/config.rs` + `src/adapters.rs` — C1 worktree confinement: bare-name `Harness.executable` values are refused at config parse; op execution threads a `cwd` (`execute_op_at`, `ProcSpec.cwd`) so harness/workspace effects run inside the worktree, never the daemon cwd.
- `tests/mutation_engine.rs` (new) — socket-level acceptance tests (real binary + daemon + fake harness executables + disposable local repositories): full lane flow (worktree -> prompt commit -> collect -> review evidence -> merge -> post-merge verify -> close issue -> cleanup with salvage), moved-integration-base staleness and the no-merge race, dirty/unmerged cleanup refusals with no direct-push path, production first-write gating over the wire, expired-grant typed refusal, and plan digest binding + idempotent replay.
- `tests/harness_adapters.rs` — C1 witness tests (bare-name executable rejection; worktree cwd confinement). `tests/daemon_rpc.rs` — apply without full typed params refuses at parse time and journals nothing.

## Acceptance-criteria mapping (AC -> test/file)

- AC1 (every effect is deterministic per step: canonical plan/digest binding, pre-action journal, under-lock revalidation, typed outcome, exact external read-back): `src/mutation.rs::plan_binding_verifies_digest_and_content_identity` (unit) + `tests/mutation_engine.rs::plan_rpc_digest_binding_and_idempotent_replay` (digest-derived plan id, `ik_` idempotency, replay returns the recorded response; tamper refuses before any journal) + every `apply_ok` in `tests/mutation_engine.rs` asserts an `ok:true` envelope whose result carries the exact read-back (worktree head, commit log, merged head, closed issue) for the step just executed.
- AC2 (material issue/acceptance edits and epoch rotation invalidate grants; bound instances die with them): `src/state.rs::issue_edit_invalidates_grant_and_engine_stops_further_mutation` and `grants_revoke_list_and_epoch_invalidation` (unit) + the moved-base merge test (`tests/mutation_engine.rs::moved_integration_base_invalidates_stale_evidence_and_refuses_merge`) and expiry/revocation refusals in the wire tests.
- AC3 (caps closed subset, capability map enforced before every effect): `revalidate_effect` capability check + `src/mutation.rs::missing_capability_and_missing_phase_refuse` (unit) and every wire apply carrying a step with a cap outside the grant is refused.
- AC4 (durable review evidence with exact-head bindings; merge without current valid evidence refused): `review_evidence` effect + m0003 evidence rows (`src/state.rs::m0003_evidence_round_trips_and_refuses_bad_bindings`) + merge gates (`check_merge_evidence`) + `moved_integration_base...` wire test (`refusal.evidence.stale`) + lane-flow test asserts the merge only proceeds after recorded evidence.
- AC5 (external-contributor mechanical enforcement + trusted-lane path): `src/mutation.rs::check_external_contributor` (unit probes in `policy_probes_bite_on_red_and_accept_green`: fork-head PR without maintainer approval refuses `EXTERNAL_APPROVAL`, with approval or same-repo head passes) + `effect_pr_update` refusal path before any forge spawn + wire coverage in `tests/mutation_engine.rs::production_pr_schedule_and_first_write_gates_bite_over_the_wire` (same-repo/trusted head passes its policy probes).
- AC6 (main/hotfix RED-GREEN policy probes; no direct-push path): `src/mutation.rs::policy_probes_bite_on_red_and_accept_green` (RED: push to integration branch, push to `main`, force push to a feature branch -> `PUSH_POLICY`; feature->main PR -> `MAIN_PR_POLICY`; partial hotfix gate -> `HOTFIX_GATE`; GREEN: feature push, staging->main PR, hotfix/*->main PR, complete hotfix gate) + `tests/mutation_engine.rs::dirty_and_unmerged_cleanup_refuses_and_no_direct_push_path_exists` (wire: no direct/force push path exists; the only promotion route is the forge PR path exercised in the production schedule test).
- AC7 (closure-after-merge with post-merge verification; promotion separate): `src/mutation.rs::issue_closure_requires_post_merge_verify_and_pass_evidence` (unit) + `tests/mutation_engine.rs::lane_flow_merges_verified_head_closes_issue_and_cleans_with_salvage` (wire: `m1` merge -> `v1` post_merge_verify -> `i1` issue close, and closing before `v1`/without pass evidence is refused `refusal.closure.premature`; promotion to `main` is not part of the lane — it is the separate `pr_update` effect gated by `check_main_pr_origin`).
- AC8 (cleanup refuses dirty/ambiguous/uncontained/unverified work and journals salvage evidence): `tests/mutation_engine.rs::dirty_and_unmerged_cleanup_refuses_and_no_direct_push_path_exists` (dirty worktree refusal, unmerged branch refusal, no push path) + cleanup containment (`contained_path`/`is_contained`, `code::UNCONTAINED` refuses escapes) + `src/state.rs::salvage_journal_record_completes_the_cleanup_audit_pair` + lane-flow test asserts the salvage audit pair (`mutate.cleanup` pre-effect intent, post-effect `salvage.cleanup` evidence with the removal read-back).
