## 2. Proof of REAL read-model consumption (which API, which call path)

Call path, exactly:

```
tui::session::run(&LiveBoard)                  src/tui/session.rs   (Crossterm session loop)
  -> tui::live::LiveBoard::snapshot()          src/tui/live.rs      (impl ReadModel, one bounded read per frame)
    -> canter::board::read_board(&State, &BoardQuery)   src/board.rs  (#83 read model: bounded page,
                                                                      deterministic (repository, issue, run)
                                                                      ordering, closed-set validation)
      -> State::board_page_rows(after, limit, per_row_cap)  src/state.rs (the authoritative bounded join)
      -> State::summary()                      src/state.rs         (epoch/journal for freshness)
    -> view_of_page(&BoardPage) -> BoardView   src/tui/live.rs      (pure mapping, closed rules)
```

Recorded `BoardRow` fields reach the surface with closed, documented rules — never invented:

| Surface field | Recorded source | Rule |
| --- | --- | --- |
| `issue` | `repository`, `issue` | verbatim (legacy rows keep their recorded empty/0 identity and stay `partial`) |
| `run` | `run` (instance id) | verbatim; `attempt: None` — the read model numbers no attempts (several runs per issue are several rows) |
| `stage` | `stage`, `run_state` | `verified`→VerifiedMerge; `new`→Ready; `running`→Implementing; `paused`/`human_queue`→HumanOnlyGate; `blocked`→Blocked; `done`→WorkerReportedDone; `invalidated`→Invalidated |
| `outcome` | same | only the read model's `verified` stage is `VerifiedDelivery`; a recorded `done` status is `ReportedDone` (unverified); else `InProgress` |
| `owner`, `reason`, `title` | `owner`, `reason` (null) | stay `None` (the read model records none; the intent side is not re-observed) |
| `next_action`, `human_gate` | `next_action`, `human_gate` | verbatim closed pointer / gate = the recorded next action |
| `evidence` | `verification`, `evidence[]`, `evidence_total` | recorded verdict ref, the recorded reference ids, plus an explicit remainder when the read model reported overflow |
| `freshness` | `source_freshness`, `source_completeness`, `progress_at`, `observed_at` | stale/complete verbatim; age measured from the recorded timestamp |
| `state`/`page` | read outcome | `Ready`/`Empty`; one bounded page — unknown totals render `page 1/?` and `N+ rows`, never a guess; a failed read is `Offline` + `read failed: <stable code>` with the last known page retained |

## 11. Fix round 90-R1 — hosted `rust-ubuntu` clippy failure (`unnecessary_mut_passed`)

Contract: `.fix-r1.md` (reviewer `rev-90-live-wiring`, verdict FAIL at `0a367bf`: hosted `rust-ubuntu`
RED on `cargo clippy --locked --all-targets -- -D warnings`). Fix commit:

Lint site, before → after (`tests/tui_live_wiring.rs`, the `forkpty` window-size argument):

```
-                &mut winsize,                       (line 1048 at the failing head)
+        let winsize_ptr: *mut libc::winsize = &raw mut winsize;   (line 1046)
+        ...
+                winsize_ptr,                        (line 1055)
```

**Removed the mutable borrow; no `#[allow]` was needed and none was added.** Why a raw pointer rather
than the shared reference clippy suggests: the libc `forkpty` signature is platform-dependent —
`*mut winsize` on BSD/macOS (`libc`'s apple module), `*const winsize` on Linux — so `&winsize` does not
compile on macOS (E0308: expected `*mut winsize`, found `&winsize`) while `&mut winsize` trips the
Linux lint. An explicit raw pointer is accepted by both signatures and leaves no mutable borrow
argument for the lint to flag.

Independent local discrimination of the lint (lane probe, host-only crate under `/tmp`, not part of the
repository; the real CI host is Linux and not available here):

  signature shape) → clippy raw exit `0` with `-D warnings` — `run/logs/probe-mutlint-fixed-form.log`.
