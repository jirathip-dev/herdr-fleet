## What changed

- `src/adapters.rs` — `Profile` carries an explicit `provider`/`model`
  binding (`Profile::with_binding`, bare-token validated). The Pi and
  Jcode prompt rows build `--provider`/`--model` from the binding;
  `prompt_args` contains no provider/model literal. An unbound (or
  half-bound) profile refuses the terminal prompt with the documented
  typed code `refusal.binding.missing` (`CODE_BINDING`) before any
  subprocess runs — no default, no fallback, no substitution. The Jcode
  `--json` envelope now also extracts the returned `provider`/`model`;
  the typed success payload carries `requested` (the declared binding)
  and `returned` (exactly what the envelope reported, `null` when it
  reported nothing — never inferred, never coerced) alongside
  `transcript`. Non-envelope stdout still falls back to the raw
  transcript with no content loss. The Herdr lifecycle mapping reuses
  the existing typed refusal mechanism: `refusal.binding.missing` on a
  terminal `prompt` reports `blocked` with the static message
  `harness provider/model binding required`.
- `src/config.rs` — `Harness` gains optional `provider`/`model`; the
  decoder validates each declared token as a bare token (non-empty, no
  whitespace, no path separators) and requires the pair together,
  refusing with the named `config.invalid` error that spells the
  `config.harness.<key>.<field>` path. `is_bare_token` is the single
  predicate also used by the adapter-side binding constructor. The
  `config init` template comment block documents the binding pair.
- `src/schema.rs` — the `hf-config/v1` document validator accepts the
  optional `provider`/`model` keys (string type; the closed key set
  stays closed).
- `src/commands.rs` — `config show --json` surfaces the declared
  binding (`provider`/`model`, string-or-null) per harness row.
- `docs/contracts/spec-config.md` — harness row + a refusal bullet:
  bare-token pair, declared together; an absent binding is not a load
  error (the prompt refuses instead).
- `docs/contracts/spec-capabilities.md` — adds `refusal.binding.missing`
  to the closed refusal-code list, a `blocked` row to the Herdr
  lifecycle mapping table, and rewrites the harness-neutrality paragraph
  (the pair is declared input; the returned identity is surfaced; a
  requested/returned mismatch is observable and never coerced).
- `scripts/check-contract-fixtures.py` — the independent fixture oracle
  mirrors the optional binding keys (string pair; decoder-only rules
  stay decoder-only).
- `scripts/test-check-contract-fixtures.py` — two new tamper cases: a
  non-string `provider` refuses malformed; a valid `provider`/`model`
  pair is accepted.
- `tests/harness_adapters.rs` — synthetic binding tokens
  (`example-provider`/`example-model`) replace the historical literals in
  every exact-argv fake; new rows: an alternate declared pair proves the
  rows follow the binding (AC1), unbound refusal without spawning
  anything (AC3), the unbound `blocked` Herdr report (AC3), the envelope
  transcript + returned identity (AC4), requested/returned mismatch
  observable and never coerced (AC4), non-envelope raw fallback with
  `returned: null` (AC4). The prompt-path Herdr log assertions were
  hardened to the settled (last) report row: `run_op_retry` may re-run
  an op once on a transient host spawn failure, which can emit one extra
  report row.
- Unrelated flake fixed while wiring coverage: the config unit test
  `resolve_repository_by_key_and_identity` loaded a config that named a
  policy overlay written by a different test into the shared
  per-process temp dir (order-dependent coupling under parallel test
  threads); it is now self-contained.
