## Schema delta (m0005)

Migration id `m0005_lane_replacements_v5`, applies 4 → 5
(`SCHEMA_VERSION` 5). Exact SQL delta (from `M0005_SQL` in `src/state.rs`):

```sql
CREATE TABLE lane_replacements (
    replacement_id TEXT PRIMARY KEY,
    lane_id TEXT NOT NULL,
    generation INTEGER NOT NULL,
    successor_generation INTEGER NOT NULL,
    phase TEXT NOT NULL CHECK (phase IN
        ('requested', 'quiescing', 'checkpointed', 'retired', 'starting', 'adopting', 'adopted')),
    outcome TEXT NOT NULL CHECK (outcome IN ('pending', 'held', 'ambiguous', 'cancelled')),
    outcome_reason TEXT NOT NULL DEFAULT '',
    source_session TEXT NOT NULL,
    source_process TEXT NOT NULL,
    role TEXT NOT NULL,
    worktree TEXT NOT NULL,
    reason TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    UNIQUE (lane_id, generation)
);
CREATE TABLE lane_replacement_events (
    seq INTEGER PRIMARY KEY,
    replacement_id TEXT NOT NULL,
    from_phase TEXT,
    to_phase TEXT NOT NULL,
    from_outcome TEXT,
    to_outcome TEXT NOT NULL,
    reason TEXT NOT NULL DEFAULT '',
    at TEXT NOT NULL
);
CREATE INDEX idx_lane_replacement_events_record
    ON lane_replacement_events(replacement_id, seq);
```

The migration is purely additive (no existing table or row is touched);
the v4 → v5 upgrade path with a stored grant is proven by
`state::tests::lane_replacement_migration_preserves_stored_grants` (raw
fixture lands at `user_version` 4, upgrades to 5, grant row and epoch come
back byte-identical).

## RPC surface (request-only)

`lane.replacement.request` · `.advance` · `.hold` · `.cancel` · `.status`
— every mutating method is idempotency-keyed and journals through the
shared claim machinery; `status` is read-only.

Why it has no spawn/kill/Git side effect and no authority uplift:

- the handler path only calls `journal_mutation`/`finish_mutation` and the
  state methods (SQLite + audit journal) — no `process::run`, no adapter,
  no Git invocation exists on it (diff review of `src/daemon.rs` handlers);
- the integration test
  `request_surface_needs_no_external_tools_and_no_authority` runs
  request → advance → status against a daemon spawned with an **empty
  PATH** (no external tool is reachable) and proves `state.epoch` and
  `grants.list` are unchanged (no grant is required, issued, or consumed);
- excluded scope honored: no retirement execution, no automatic triggers,
  no successor execution, no scheduler, no whole-fleet restart, no
  main/release/production effect — the record is durable intent only.
