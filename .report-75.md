## The retirement protocol (as implemented)

- **Binding (AC1).** `params.binding` = {generation, session, process,
  checkpoint_digest} is the plan/grant unit of this slice. It must match the
  durable record (`generation`, `source_session`, `source_process`) and the
  committed checkpoint of that record (`digest` and the checkpoint's own
  generation) or the request refuses with `refusal.retirement.binding` —
  BEFORE any effect. The paused state refuses too: a `held` record answers
  `refusal.replacement.held` (the lifecycle park verdict), a cancelled
  record `refusal.replacement.invalidated`, an ambiguous record
  `refusal.replacement.ambiguous`, and a record that is not at the
  `checkpointed` boundary `refusal.replacement.order`. The request itself is
  journaled as a claim like every daemon mutation, so the exact binding
  (checkpoint digest included) is durable in the claim's request line and
  the audit journal. Interpretation note: the issue's "Plan/grant" is
  implemented as this request binding document plus the daemon's journaled
  claim; no grant is issued or consumed (mirroring #73/#74, whose surfaces
  are also grant-free).
- **Immediate pre-stop quiescence recheck (AC2).** `params.recheck` =
  {observed_at, session, process, children[{command,state}], active} is
  validated in the same read that binds the record, immediately before the
  stop: every observed child must be `exited` and external execution must
  not be active, or the retirement HOLDS (`refusal.retirement.held`); a
  missing/non-actor process identity is an unknown identity and HOLDS; an
  observed identity that differs from the record refuses as a binding
  mismatch. A hold writes nothing and signals nothing — no process group is
  ever addressed, nothing is killed or cleaned up to obtain quiescence.
- **Bounded graceful stop (AC3).** The only stop this slice can issue is ONE
  `session interrupt <session> --json` row through the existing
  workspace (Herdr) adapter path under the adapter deadline (10 s). There is
  no retry, no SIGKILL, no broad pattern, no process-group signal and no
  authority escalation anywhere on the path. A stop that never ran (the
  workspace executable is unavailable) refuses with
  `refusal.unavailable.harness` and leaves the record untouched; any other
  non-success parks the record `ambiguous` (`refusal.retirement.held`) with
  the no-repeat decision in the reason.
- **Backend-evidence confirmation (AC4).** After the stop, ONE
  `session show <session> --json` read must show the backend process absent
  AND the ownership/registration released for the bound session and
  generation. The read-back's own label (`state`, `done`, pane text) is
  never read, so a label alone can never confirm a retirement. A different
  process under the bound session, a read-back naming another session, or a
  stale registration (another session/generation) fails closed
  (`refusal.retirement.reused`) and parks the record `ambiguous`; missing,
  unknown or unparsable evidence holds the same way.
- **Children and bytes (AC5).** The retirement addresses only the record's
  own bound session identity; child worker/reviewer records, the lane's
  worktree and every report byte are never touched (the retirement never
  resolves the worktree and never runs a command outside the two session
  rows).
- **Crash after the stop (AC6).** `lane-retire.after-stop` aborts the daemon
  after the stop and before the outcome is journaled. On the next start the
  interrupted claim is reconciled through the confirmation read only: one
  `session show` read; verified exact absence completes the
  `checkpointed` → `retired` transition with a reconciled evidence summary,
  and every other outcome (still present, reused identity, unreadable
  backend) parks the record `ambiguous` with the no-repeat decision
  recorded. Reconciliation never issues a stop, and never against a reused
  identity.
- **Adapter path.** The retirement's only wired adapter path is the
  workspace (Herdr) session rows. A profile that does not declare both the
  `interrupt` and `observe` capabilities is an unsupported adapter and
  refuses with `unknown.capability` BEFORE the claim (no state change,
  nothing signalled); an unknown kind refuses with `unknown.harness`.

## Not proven / caveats

- Hosted CI (rust-ubuntu, rust-macos, policy) was not run from this lane; the
  local aggregate plus the read-only oracle replica are the evidence
  available here.
- The retirement's adapter rows (`session interrupt`, `session show`) are a
  v1 candidate workspace contract, pinned by fake executables exactly like
  the other adapter rows [awaiting-evidence] until the human-gated
  clean-host matrix; no real session was stopped or inspected by this lane.
- The recheck observation is client-supplied evidence validated against the
  durable record (the #74 observation pattern): the daemon binds it, the
  stop is issued immediately after the validating read, and the *backend*
  confirmation is the independent check afterwards. If the reviewer reads
  AC2 as "the daemon must itself observe quiescence", the code and tests
  make the implemented scope explicit so the delta can be adjudicated
  directly.
- No durable retirement table was added (no schema change): the phase
  transition, its history row, the claim's request line/response and the
  audit journal carry the durable evidence. A future slice that needs a
  queryable retirement record can add it additively (m0007) without
  reinterpreting anything shipped here.
- Diagnostics/decisions on this lane are recorded against `Refs #75`; no
  issue, PR, or remote branch other than this lane's branch is touched.
