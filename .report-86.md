## Acceptance points, each pinned by a named test

**AC1 — stop-admitting precedes any new owner; in-flight work is preserved;
status distinguishes *requested* from *reached*.**

- `tests/run_control.rs::wire_pause_stops_dispatch_before_the_boundary_and_reaches_it_when_the_step_resolves`
  — a REAL step dispatch is held in flight (a fixture `git` shim keeps the
  checkout effect running for ~a second, and `run.status` is polled until
  `boundary.in_flight_step == "p1"`); `run.pause` then answers
  `control.state == "pause_requested"`, `boundary.reached == false`, and a
  further `apply` is refused `refusal.run.paused` *before any effect*; when
  the in-flight step reaches its recorded outcome the boundary commits on the
  daemon's own path (`state == "paused"`, `boundary.reached == true`) with the
  same digest.
- `tests/run_control.rs::state_pause_request_waits_for_the_recorded_boundary_then_commits`
  — the state machine: in-flight claim ⇒ request recorded, boundary not
  committed; the claim resolving ⇒ commit exactly once; idempotent
  afterwards.
- `tests/run_control.rs::state_pause_is_immediate_at_the_boundary_durable_and_exact_targeted`
  — with nothing in flight the boundary is already reached and the pause
  commits immediately; the intent survives a store reopen; a second pause
  refuses `refusal.run.control`.
- `tests/run_control.rs::wire_pause_intent_survives_a_daemon_death_and_commits_on_restart`
  — SIGKILL with the step in flight: the durable row still carries
  `pause_requested`; the restart commits the reached boundary and dispatch
  stays refused.

**AC2 — resume requires the engine-minted digest, fresh eligibility and an
exact target; it never clears an unrelated pause.**

- `tests/run_control.rs::wire_resume_is_exact_target_and_never_clears_an_unrelated_pause`
  — two runs are paused; a foreign digest refuses `state.stale_resume`, a
  wrong digest refuses `state.stale_resume`; resuming A leaves B paused with
  B's own digest intact; there is NO fleet-level control (`fleet.pause`,
  `fleet.resume`, `fleet.unpause` are outside the closed method set) and a
  lane-shaped or malformed target refuses `refusal.run.target`.
- `tests/run_control.rs::state_resume_refuses_a_stale_epoch_and_never_touches_a_second_run`
  — after an epoch rotation the authorization refuses `refusal.state.epoch`
  and the second run is left untouched.
- `tests/run_control_cli.rs::cli_run_controls_round_trip_through_the_real_daemon`
  — the CLI surface: a wrong digest is refused typed (exit 1) and the exact
  digest resumes exactly that run.

**AC3 — a retry names exactly ONE diagnosed eligible step; invalid, revoked,
stale and terminal-success retries refuse.**

- `tests/run_control.rs::wire_retry_names_one_diagnosed_step_and_refuses_every_ineligible_one`

  out-of-order step refuses `refusal.run.step_order`, an unattempted step
  refuses `refusal.run.step_undiagnosed`; the authorization is single-use

- `tests/run_control.rs::wire_retry_refuses_a_revoked_grant_and_a_succeeded_step`

- `tests/run_control.rs::wire_retry_refuses_a_stale_epoch`
  — after an epoch rotation the retry refuses `refusal.state.epoch`.
- `tests/run_control.rs::state_bounded_retry_is_single_use_and_bounded`

| --- | --- | --- | --- |
| run | `run-` + 16 hex `instance_id` | `run.pause` / `run.resume` / `run.retry` / `run.status` | exactly this run: stop admitting new steps, lift THIS run's pause, authorize ONE bounded re-dispatch of ONE diagnosed step |

## Boundary proof — pause reaches a safe boundary before any further dispatch

`tests/run_control.rs::wire_pause_stops_dispatch_before_the_boundary_and_reaches_it_when_the_step_resolves`
drives the honest sequence against the real daemon:

1. a step dispatch (`apply` for `p1`) is HELD in flight (fixture `git` shim
   sleeping ~1 s; `run.status` polled until `boundary.in_flight_step ==
   "p1"`);
2. `run.pause` records the durable request and answers
   `state = "pause_requested"`, `boundary.reached = false`,
   `in_flight_step = "p1"` — the in-flight work is reported, never cancelled;
3. a second dispatch (step `p2`) is refused `refusal.run.paused` BEFORE any
   effect (the effect adapter is never reached — proven by mutation probe P1,
   where removing the fence makes that same request execute and fail in the
   adapter instead);
4. the in-flight step resolves, and only then does the boundary commit
   (`state = "paused"`, `reached = true`), keeping the same resume digest;
5. a restart keeps the reached pause and the digest; dispatch stays refused;
   only the exact digest resumes, and the next dispatch is no longer fenced
   by the pause.

The library-level pins (`state_pause_request_waits_for_the_recorded_boundary_then_commits`,
`state_pause_is_immediate_at_the_boundary_durable_and_exact_targeted`) prove
the same transition without a daemon, and
`wire_pause_intent_survives_a_daemon_death_and_commits_on_restart` proves the
request is durable across a SIGKILL.

## Not proven / deliberately out of this slice

- **No fleet-level or lane-level control exists by design** (hard exclusion in
  the brief): there is no fleet unpause, no kill/kill-all, no destructive
  cleanup and no gate bypass anywhere in the diff. The controls cannot resume
  a human-paused fleet and cannot lift a hold expressed on another run.
- **The in-flight step is never cancelled** — the pause commits at the
  *recorded* boundary. "In-flight dirty work is preserved" is proven by the
  held-step scenario, not by an assertion that a running process survives an
  unbounded time (the daemon signals nothing).
- **Not verified here**: behaviour against a live remote (`gh`), a live
  Herdr/harness process, or the running fleet supervisor — this slice has no
  network surface and touches neither; the tests use synthetic identities and
  local fixture state only.
- **Not verified here**: a pause landing while a step executes inside a
  spawned harness process (no harness is spawned in tests; the admission gate
  is exercised only through its refusal paths).
- The lane's brief-prescribed build directory is not part of the diff and was
  removed at closeout.
