## 1. What is proven

### 1.1 The compact status reads the real recorded #95/#96 state

Command: `cargo test --locked --test tui_supervision
the_compact_status_reads_the_real_recorded_supervision_state`.

A real `canter daemon run` holds the fixture store; an ARMED submission is
committed through the daemon's own `queue.submit` (the CLI's params document
with `--supervise arm`, built by `queue_executor::submit_params`, never
hand-assembled). The console then reads the status with the exact keystroke
path `j s` (select the recorded run, open the supervision screen) and the test
compares the panel field-by-field against the SAME document an independent
client reads over the socket:

- `class_code`, `reason`, `checks`, `continuation.open`, `eligible` are equal
  to the daemon's recorded `evaluation.*` values (the panel renders data, it
  does not re-classify);
- the compact screen carries every field the brief names: `status:`,
  `reason:`, `blocked reason:`, `evidence:`, `last check:`,
  `next eligible check:`, `continuation window:`, `authorization: armed`,
  `run control:`, plus the run identity and the one technical disclosure;
- back on the board (`Esc`) the SAME reading renders as the one-line strip
  `supervision: …` (asserted in `lines()`/frame form and by the rendered
  TestBackend frame at 120×40);
- the fixture proves the positive control: the CLI-armed submission records a
  supervision row (`state.supervision_rows()` non-empty), which is what makes
  §1.5's empty-table statement meaningful.

### 1.2 Each control reaches the REAL typed service (exact keystroke path)

Command: `cargo test --locked --test tui_supervision
each_guarded_control_reaches_the_real_typed_service -- --nocapture`.

The test prints the exact keystroke paths it drives and the recorded values:

```
keystroke path: j s h SPACE ENTER  (hold run-<16hex>)
keystroke path: u SPACE ENTER      (continue run-<16hex> with digest <HEX64>)
```

- HOLD: `h` (open the confirmation) → `Space` (set the box) → `Enter`
  (commit). The console sends `run.pause` with
  `run_control::pause_params(key, run, reason)` — the CLI's own params
  document, key set `{idempotency_key, instance_id, reason}` asserted at the
  wire in §1.3. The daemon's committed control document reports
  `state = pause_requested|paused`; the durable instance row carries
  `pause_requested/paused` and `pause_reason == PAUSE_REASON`; an INDEPENDENT
  `run.status` call reads the same state back.
- CONTINUE: `u` → `Space` → `Enter` sends `run.resume` with
  `run_control::resume_params(key, run, digest)` where `digest` is the
  recorded resume digest the `run.status` read surfaced (asserted equal to
  the confirmed confirmation's digest and to the wire params in §1.3). The
  durable row afterwards: `paused = false`, `resume_digest` cleared.

### 1.3 No keyboard path arms supervision or advances a gated run (wire proof)

Command: `cargo test --locked --test tui_supervision
no_keyboard_path_arms_supervision_or_advances_a_gated_run`.

A recording peer socket captures EVERY request line (method + params) while
the console is driven through adversarial key sequences: bare `Enter`;
`h`+`Enter` without the box; `h`+`Space`+`Esc`+`Enter`; `h`+`Space`+REPEAT
`Enter`; `h`+`Space`+RELEASE `Enter`; `u`+`Enter`; `u`+`Space`+`Esc`+`Enter`;
and a navigation/editing sweep (Tab, BackTab, arrows, Home, End, Delete).

Asserted outcomes:

- zero `run.pause`/`run.resume` requests from any adversarial sequence; no
  attempt is recorded at all;
- the ONLY deliberate paths produce exactly one `run.pause` (params
  `{idempotency_key, instance_id, reason}`, `reason == PAUSE_REASON`) and one
  `run.resume` (params `{digest, idempotency_key, instance_id}`,
  `digest == peer.digest`);
- every recorded method is inside the closed set `{run.status,
  supervision.status, run.pause, run.resume}` — no `queue.submit`, no
  `run.retry`, no supervision arm/nudge method is ever reached, so no
  keyboard path enables or advances supervision.

### 1.4 The operator submit path never arms supervision on the operator's behalf

Command: `cargo test --locked --test tui_supervision
the_operator_submit_path_never_arms_supervision_on_the_operators_behalf`.

The real operator authority path (`j` select, `p` preview, `Enter`,
`Space`, `Enter` authorize) submits through the daemon with the presented
reviewed plan. Afterwards `state.supervision_rows()` is EMPTY and
`state.supervision_by_id(admitted_run)` is `None`, while the same fixture's
CLI-armed submission DOES create the row (§1.1 positive control). Enabling
supervision therefore remains the CLI's explicit `--supervise arm`
authorization only.

### 1.5 A pause holds across a TUI restart and is never replayed

Command: `cargo test --locked --test tui_supervision
a_pause_holds_across_a_tui_restart_and_is_never_replayed`.

Session 1 holds the run through the panel (`s h SPACE ENTER`); the console is
dropped (terminal closed). A FRESH console (reopen) reads the recorded state:
`control.recorded_pause()` is true, the second hold is disabled with a reason,
the recorded resume digest survives, and a benign key sweep (`Enter`, `r`,
`j`, `k`, `h`, `Esc`) effects nothing — the hold still holds, the run's
recorded step-attempt count is unchanged (no step dispatched, no replay) and
the instance count is unchanged (no second submission). Only the explicit
`u`/`Space`/`Enter` continue lifts exactly that pause.

### 1.6 Missing/stale/unreadable evidence never reads healthy

Commands: `cargo test --locked --test tui_supervision
stale_evidence_reads_held_and_never_healthy_over_the_real_daemon` and the
module unit tests (`cargo test --locked --lib tui::supervision`).

- live: after the first committed check (fresh), the recorded
  `supervisions.last_check_at` is aged past the recorded freshness bound with
  a raw UPDATE on the fixture database; the daemon's OWN
  `supervision.status` then reports `freshness.state = stale`, and the panel
  reads `trusted() == false`, `held() == true`, `class_slot()` leads with
  `stale …` and the rendered screen says `evidence: stale … (held)`;
- unit pins (synthetic documents): unreadable → `unknown … held`; missing →
  `unknown — no committed check yet (held)`; an unrecognized recorded class
  maps to `Unknown` (the raw code is displayed as recorded, never as a known
  class); a not-armed run reads `disabled — not armed`; only fresh committed
  evidence reads its recorded class.

### 1.7 A real terminal holds a run with real key bytes

Command: `cargo test --locked --test tui_supervision
a_real_terminal_holds_a_run_through_the_supervision_screen -- --nocapture`.

The REAL `canter board` binary runs under a genuine `forkpty` terminal
(120×40) against the fixture daemon; the harness sends the exact key bytes
`j s h SPACE CR r q`. The captured terminal stream (printed by the test)
shows the board strip, the `SUPERVISION` screen with the compact status, the
`HOLD REQUEST` confirmation, and the requested-vs-observed outcome; the
daemon's durable row afterwards carries the hold with `PAUSE_REASON`.
