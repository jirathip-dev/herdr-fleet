## The checkpoint protocol (as implemented)

- **Fence (AC1).** While a pending replacement for a lane sits inside the
  quiescing window (`quiescing` or `checkpointed`), a new replacement
  request for that lane refuses typed (`refusal.replacement.fenced`) — a
  lane cannot fork into a second successor slot mid-handoff — and capture
  itself is admitted only at the exact `quiescing` boundary (a
  `requested`-phase record refuses through the existing typed transition
  classifier, a stale generation refuses `refusal.replacement.stale`).
  The fence lifts when the handoff resolves (retired onward) or is
  cancelled/held. Interpretation note: the issue's AC1 phrase "quiescing
  fences new daemon-mediated actions for the source generation" is
  implemented as this generation fence plus the acknowledgment/observation
  gate below; the daemon makes no claim about arbitrary shell actions.
- **Acknowledgment + observation (AC1/AC2).** The capture request carries
  TWO observations of the lane (`observation`, `reobservation`); they must
  be canonically identical or the checkpoint refuses
  (`refusal.checkpoint.changed`) and commits nothing. With active external
  harness execution declared, a supported quiescence acknowledgment
  (`session-quiesced`, actor identity + timestamp) AND a process/child
  observation are required (`refusal.checkpoint.ack` otherwise; an
  acknowledgment supplied while execution is inactive is refused, never
  ignored). The closed observation document carries role/task,
  worktree/branch/head/base, dirty + untracked inventory with their 64-hex
  integrity digests, report round + exact reviewed sha, bounded pending
  gates, observed child commands, and the execution/ack block; missing or
  invalid required evidence refuses (`refusal.checkpoint.incomplete` — it
  is never silently omitted).
- **Holds (AC2/AC6).** An observed side-effecting child command that is
  active or ambiguous holds completion (`refusal.checkpoint.held`); the
  daemon has no signalling surface at all, so nothing is killed or cleaned
  up to obtain a snapshot, and the hold is not durable — the caller retries
  once the child exits. Required data whose generated brief exceeds the
  enforced 3 KiB bound is a typed hold (`refusal.checkpoint.oversize`);
  required gates are listed in full, never truncated.
- **Snapshot (AC3).** The committed snapshot binds the replacement facts,
  the validated observation, the daemon-observed outstanding operations
  (in-flight claims other than the capture itself, with the exact total),
  the state epoch and capture time; the snapshot digest is sha256 over its
  canonical bytes.
- **Orchestrator references (AC4).** Orchestrator-role checkpoints must
  reference EXISTING worker (implementer) and reviewer replacement records
  plus bounded pending completion-event tokens; unknown, role-mismatched or
  misplaced references refuse (`refusal.checkpoint.references`), and
  referencing lanes leaves their records and history byte-identical.
- **Atomic commit + restart (AC7).** The checkpoint row, the record's
  `quiescing` → `checkpointed` transition and the history row commit in
  ONE transaction (the commit marker). The compact brief is generated
  deterministically from the committed row and materialized after the
  commit; restart reconciliation treats the row as the marker — the brief
  is (re)generated and verified against `brief_digest` (yielding the
  previous complete checkpoint or the new complete one), and an artifact
  without a committed record (only a non-atomic implementation produces
  one) fails closed: the record is parked `ambiguous`, never adopted or
  silently deleted.

## Not proven / caveats

- Hosted CI (rust-ubuntu, rust-macos, policy) was not run from this lane; a
  read-only local replica of the policy corpus is the oracle above
  (65/65), and the aggregate is the local evidence available here.
- The audit clock-race fix has no dedicated regression test: the crate has
  no clock-injection hook, so the race cannot be forced deterministically
  in-test. The observable invariant it protects (audit chain verification
  at every state open) is exercised by every restart in the crash/restart
  flows of `tests/checkpoint.rs` and the existing daemon suites.
- The 3 KiB brief bound is a design choice, enforced fail-closed with a
  typed hold; the oversize path is proven with maximal legal input in both
  the state-layer and socket-level tests.
- The fence scope is stated in the protocol section above; if the reviewer
  reads AC1's fence sentence differently, the code and tests make the
  implemented scope explicit so the delta can be adjudicated directly.
- Diagnostics/decisions on this lane are recorded against `Refs #74`; no
  issue, PR, or remote branch other than this lane's branch is touched.
