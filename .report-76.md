## Per-AC statement (issue #76 acceptance list)

1. **Verified source retirement + checkpoint integrity; one generation/nonce
   owns startup; simultaneous/replayed starts cannot create duplicate
   successors.**
   `start_requires_the_retired_boundary_and_checkpoint_integrity` — a
   non-retired record refuses `refusal.replacement.order`; a changed
   checkpoint digest, a wrong generation, a bound-session mismatch and a
   missing/empty startup nonce refuse `refusal.successor.binding`; a live
   source refuses `refusal.successor.source_live`; every refusal invokes
   NOTHING (the invocation log is unchanged) and leaves the record plus its
   history untouched; the exact request then commits ONE successor and
   issues exactly the bounded sequence `session show <source>` →
   `session start <successor>` → `session show <successor>`.
   `duplicate_starts_cannot_create_a_second_successor` — a same-nonce
   replay refuses `refusal.successor.exists`; a different nonce refuses
   `refusal.successor.nonce`; two SIMULTANEOUS starts with different
   keys/nonces return exactly one `ok`, issue exactly one `session start`
   and keep the SAME successor id (the `UNIQUE (replacement_id)` row).
2. **Existing concurrency/resource/grant gates apply; a capacity refusal
   stays held with bounded retry, never disables admission; no recurring
   scheduler.**
   `capacity_refusal_is_a_held_typed_refusal_with_a_bounded_retry` — a
   missing host proof refuses `refusal.admission.proof_missing`, a stale
   proof `refusal.admission.proof_stale`, an exhausted global cap
   `refusal.admission.cap_global`; each hold leaves the record
   `retired`/`pending`, invokes nothing, keeps admission enabled, and one
   explicit fresh request then starts successfully (the surface exposes no
   timer/scheduler API, so no recurring scheduler exists to disable
   admission).
3. **Successor uses the SAME worktree and logical task; no new duplicate
   branch, reset or cleanup; source and successor both live/ambiguous ⇒
   block advancement.**
   `successor_uses_the_same_worktree_and_blocks_when_the_source_is_live` —
   a still-live source refuses `refusal.successor.source_live` before the
   boundary commit and before any invocation; the successor row carries
   the record's worktree/role (the adapter verification requires cwd ==
   that worktree; a different cwd classifies `Reused`), and the path has no
   branch/reset/cleanup effect at all.
   `a_spawned_process_alone_is_not_adopted` — a reused/ambiguous successor
   parks the record `ambiguous`, which blocks advancement until external
   reconciliation.
4. **Verify fresh session identity, role/profile/cwd, kickoff receipt and
   adapter-observed readiness. A spawned process alone is not ADOPTED.**
   `a_spawned_process_alone_is_not_adopted` — a process-only read-back, an
   absent session, a missing readiness, a malformed read-back and an
   undecided-verification attempt all refuse `refusal.successor.held`; a
   reused or wrong identity parks `ambiguous`. The durable verification
   evidence (session, process, role, profile, worktree, kickoff receipt,
   readiness) is recorded on the successor row with a 64-hex digest, as
   asserted by test 1.
5. **Adoption re-queries heads, dirty inventory, live children, reports and
   gates; differences trigger reconciliation, never blind replay or stale
   PASS reuse.**
   `adoption_reconciles_instead_of_replaying_a_difference` — a difference in
   head, base, dirty inventory, untracked inventory, report, gates or
   children each refuse `refusal.successor.differs` naming the field and
   park the record `ambiguous` (reconciliation, never an adoption); two
   non-canonically-identical re-queries refuse `refusal.successor.binding`;
   the unchanged re-query adopts once. PR/CI: the comparison covers every
   field the fresh re-query carries; this bounded slice adds no PR/CI
   provider probe (see "Not proven / caveats").
6. **Orchestrator replacement preserves worker/reviewer identity; a worker
   completion during the handoff is durably reconcilable and consumed
   idempotently after adoption with no duplicate reviewer dispatch.**
   `orchestrator_identity_is_preserved_and_completions_consume_once` —
   the orchestrator successor keeps the retired session's role and the
   record's orchestration block (worker/reviewer references); a completion
   recorded during the handoff is consumed exactly once with
   `consumed_at`/`consumer`/`consumed_events` persisted; a second
   consumption refuses `refusal.successor.event_consumed`, an event that
   was never recorded refuses `refusal.successor.event`, and consumption
   before adoption refuses `refusal.replacement.order` — no duplicate
   reviewer dispatch is possible.
7. **PAUSED between transitions prevents launch/activation; a booted
   successor remains fenced; a daemon restart reconciles the startup nonce
   and process evidence before any retry.**
   `paused_between_transitions_fences_the_successor` — holding the record
   refuses the start, and after a verified start holding refuses the
   adoption while the booted successor stays `adopted_at` empty and the
   paused activation invokes nothing (the fence holds a booted successor).
   `restart_reconciles_the_startup_nonce_and_process_evidence_before_any_retry`
   — a crash after the boundary commit (before the spawn) is reconciled on
   restart: the committed successor is read back and the `starting` →
   `adopting` boundary completes with NO second spawn; with process-only
   evidence the same read-back parks the record `ambiguous`, the retry
   refuses `refusal.replacement.ambiguous` and ZERO `session start`
   invocations occur.
   `adopt_crash_and_fresh_retry_after_restart` — an interrupted adoption
   claim commits nothing, repeats nothing and spawns nothing; a fresh
   request reconciles the same evidence and adopts exactly once.
8. **Fake-adapter/socket tests cover absent successor, duplicate successor,
   missing ack, changed head, pending human approval and worker completion
   during handoff.**
   `absent_successor_and_missing_ack_are_typed_refusals` (absent successor
   boundary → `refusal.replacement.order`, nothing invoked; missing kickoff
   ack → `refusal.successor.held`; an undelivered boundary
   (`delivery: none`) retries the bounded spawn with the attempt counter
   recorded; an unresolvable workspace executable →
   `refusal.unavailable.harness` with the boundary left retryable),
   `duplicate_starts_cannot_create_a_second_successor` (duplicate),
   `adoption_reconciles_instead_of_replaying_a_difference` (changed head /
   dirty / children / report / gates),
   `paused_between_transitions_fences_the_successor` (pending human
   approval = the held/paused record — a booted successor is never
   activated) and
   `orchestrator_identity_is_preserved_and_completions_consume_once`
   (worker completion during the handoff).

## Not proven / caveats

- **PR/CI re-query**: AC5 names "PR/CI where applicable". The adoption
  re-query compares the complete fresh observation the caller supplies
  (heads, dirty inventory, children, report, gates) against the durable
  checkpoint snapshot; this bounded slice adds NO PR/CI provider probe
  (there is no PR/CI adapter on the retirement path it pins). Where a
  PR/CI fact is carried in the observation it is compared like every other
  field.
- **Kickoff receipt**: `successor.kickoff_receipt` is a 64-hex digest that
  the adapter read-back must echo; the receipt's own content is never
  interpreted.
- **Hosted CI was not run from this lane**; the local aggregate (`just ci`,
  raw exit 0) is the gate evidence available here.
- **Excluded by the issue and not implemented**: automatic rotation
  triggers, fleet-wide replacement, watchdog deployment, production
  activation, process-tree cleanup, scheduler-driven successor work and
  automatic retries (the bounded retry is one explicit fresh/same-nonce
  request). Existing paused state is untouched.
- The crash-point hooks are honored in debug builds only (release binaries
  ignore `HERDR_FLEET_CRASH_POINT`), matching the existing #73/#74/#75
  pattern; the adapter rows are pinned by fake executables exactly like the
  earlier slices [awaiting-evidence] until a human-gated clean-host matrix.
