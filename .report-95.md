## Contract surface

- The closed RPC method set grows by exactly one: `supervision.status`
  (`src/schema.rs`, 35 → 36), mirrored by
  `scripts/check-contract-fixtures.py`.
- `supervision.status` is a **read-only** method: the CLI issues it through
  the existing closed read-only allowlist (`canter supervision status`), so a
  status read can never arm, disable or nudge the driver.
- `hf-supervision/v1` is a module-local document (the `hf-queue-preview/v1` /
  `hf-run-control/v1` convention): one document, rendered identically by the
  daemon method and the human surface, with `STATEMENT` naming the closed
  boundary ("evaluation only … NO harness/LLM/process effect occurs in this
  slice").
- Authorization is the optional `params.supervision` block on
  `queue.submit` (`--supervise arm|off`): validated against a closed policy
  (`check_interval_secs` 5..3600, `progress_timeout_secs` 60..86400) and
  committed with the submission. Absent = supervision stays disabled for
  every admitted run.
- Wake model: ONE coalesced wake slot per run
  (`supervision_triggers.instance_id` PRIMARY KEY) fed by the durable event seam
  (`fold_supervision_events` folds `mutate.*`/`queue.*` journal actions into
  the slot, keeping the highest seq), plus a bounded timer fallback. A
  committed daemon mutation also signals the driver's condvar
  (`publish_after_state_change`) — coalescing, never a second scheduler.

## Restart, clock movement and the controllable clock

- **Restart**: the pause hold, the retry rows and the event cursor are read
  back from SQLite after `SIGTERM` → new daemon process
  (`…::restart_preserves_the_pause_hold_and_yields_one_fresh_reconciliation`).
  The boot sweep reconciles **every armed run exactly once** (`boot` trigger,
  `consumed_all` clears whatever the slot held), so however many windows the
  host missed while down, exactly one fresh snapshot reconciliation lands.
- **Clock movement / sleep**: the driver never replays missed windows —
  `check_plan` re-anchors `next_check_unix` to `now + check_interval_secs`
  (`a_clock_jump_re_anchors_the_next_check_and_never_replays_missed_windows`
  simulates a ten-hour sleep from an explicit clock and asserts one check, a
  future next check, and an empty due set afterwards).
- **Controllable clock**: the module's time decisions are pure functions over
  an explicit `now_unix` (`check_plan`, `next_check_unix`, `classify`,
  `fold_supervision_events`); the driver thread reads the clock through
  `crate::time` exactly once per pass and hands it down. No test sleeps to
  advance time; the daemon-level waits are bounded polls
  (`wait_for_class`, `wait_for_checks`, `wait_ready`) over recorded state.
- **Lost retention**: if the audit window no longer covers the run's cursor,
  the fold reports `lost` and the driver takes a fresh snapshot wake instead
  of pretending the events were seen (`retention_loss_falls_back_to_a_fresh_snapshot_wake`).

   `mutate.harness_start` / `mutate.prompt` / `mutate.merge` /
   `mutate.branch_push`, and the daemon log contains no `spawn` and no

3. **Read-only surface**: `canter supervision status` goes through the closed
   read-only method allowlist, and the wire test asserts three consecutive
   reads leave the progress observation byte-identical and the check count
   unmoved (`a read is not a check`).

The driver writes exactly one thing: its own run-scoped reconciliation row
(and the coalesced wake slot it consumed). It never enqueues a step, never
resumes a pause, never authorizes a retry, never touches Git, and never calls
the harness.
