## What jcode is (issue evidence, restated)

1jehuang/jcode — MIT, Rust, "most RAM efficient harness" claim (~28MB RSS
per session upstream). One-shot `jcode run -p <provider> -m <model>`
headless row with `--json` machine-readable output; `jcode serve` /
`jcode acp` exist but are NON-GOALS. Built-in providers include DeepSeek
(env key pattern), Anthropic, OpenAI-compatible. Darwin arm64 canary
(2026-09-08, v0.84.0, SHA-verified, DeepSeek): INI-parser task -> 12/12
self-written tests, ~32s wall, peak RSS ~19.9 MB, clean immediate exit.

## Verified real-binary facts (v0.84.0 linux-x64, SHA-256
e00eaede1a4f26812e77382bda9d82e2d301affd983d18ada38fddd43dce9571,
verified against the release SHA256SUMS 2026-09-08)

- `jcode --version` -> `jcode v0.84.0 (57d587899)` (exit 0). Adapter
  probe result: `present=true version=Some("0.84.0") compatible=Some(true)
  code=None` (measured through the adapter driver).
- The documented row is accepted by the real binary: `jcode run
  --provider deepseek --model deepseek-chat --json -- <message>` parses
  cleanly (`--` end-of-options guard works) and exits 1 with the measured
  missing-key text when no provider key is present:
  `Error: DEEPSEEK_API_KEY not found in environment or
  <home>/.config/jcode/deepseek.env` -> adapter classifies
  `refusal.credentials` (closed marker `api_key not found in
  environment`).
- With a synthetic invalid key the same row reaches the real DeepSeek API
  and exits 1 with `status: 401 Unauthorized` + masked-key response text
  -> adapter classifies `refusal.credentials` (existing `unauthorized`
  marker); 877 ms incl. the network round trip.
- `--json` success envelope shape (real binary, exit 0, measured through
  a local OpenAI-compatible SSE endpoint — no real credential): one
  top-level JSON object on stdout with `session_id`, `provider`, `model`,
  `text` and `usage` fields; `text` carries the final answer. The adapter
  parses `text` into the typed transcript and falls back to raw stdout
  for non-envelope output (defensive; pinned by fixture tests).
- No `skills` subcommand or `--skill` flag in v0.84.0 help (skill
  consumability documented honestly in SKILL.md).
