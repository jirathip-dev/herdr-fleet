## Digest fields bound (AC1)

`digest` = sha256 over the canonical bytes of the rendered `request`
document; the same field-set is what an authorization binds:

- `repository` — the normalized configured identity (`owner/name`,
  ASCII-lowercased);
- `host` — the explicit bare-token host identity (never inferred);
- `workflow` — `{id, hash}` (the configured pin);
- `role_config` — `{key, revision}`: the presented `hf-profile-binding/v1`
  document revalidated through the existing `ProfileBinding::from_doc` (a
  tampered revision refuses with `refusal.profile.revision`) and its
  recomputed revision bound;
- `boundary` — `{phase, caps[], integration_branch, completion_branch}` from
  the closed grant phase/capability sets;
- `steps` — the declared executable spine `[{id, kind, params}]`;
- `selected` — per issue, sorted by normalized identity:
  `{id, work_item, revision, requires[]}`.

Deliberately NOT bound (documented in the module): display titles and all
observed state (host availability, occupancy attestation, credential
presence, running lanes). Observations produce holds; the authorization binds
the plan, and admission is revalidated at run time exactly like the existing
fan-out gate.

Stable-identity normalization rule implemented: `owner/name#number`; the
bare forms `#123` / `123` resolve against the explicit repository; the
repository component is ASCII-lowercased before validation, so case variants
are one identity; duplicate presentations collapse to ONE item with a union
of requirements; two presentations of one identity with conflicting spec
revisions are refused (`usage.queue_issue`). Titles are display text that
never identify, dedupe or enter the digest.

## Acceptance points, each pinned by a named test

1. **Stable identities + digest bindings.**
   `identities_normalize_and_dedupe_on_the_stable_form_never_on_titles`
   (case/bare/duplicate presentations collapse to one `owner/name#number`
   item with the same `wi_` work-item id; reordering and titles leave the
   digest unchanged; different issues sharing a title stay two items),
   `same_inputs_yield_identical_bytes_and_digest_and_the_digest_binds_the_rendered_inputs`
   (the digest equals sha256 over the rendered bound inputs, which carry
   repository/host/workflow/role-config revision/boundary/selected
   revisions/step bindings), and
   `the_repository_identity_is_sourced_from_loaded_configuration` (the bound
   identity comes from a loaded `hf-config/v1` document, not free-form
   input).
2. **Dependency order, eligible/blocked/already-owned, concurrency.**
   `dependency_order_and_statuses_are_shown_and_unresolved_dependencies_are_never_scoped`
   (items render in dependency order; a dependency that is not in the
   selected set blocks its dependent with a named hold and is never added to
   scope; every rendered status is in the closed `ITEM_STATUSES` set),
   `ownership_and_stale_revisions_are_reported_from_durable_state`
   (already-owned items report the durable run facts; a paused run still
   owns its issue while the gate's counted set excludes it),
   `concurrency_is_shown_and_exhausted_capacities_are_named_holds` (running

   `refusal.admission.cap_*` / `refusal.admission.monorepo_overlap` holds),

3. **Named holds, not apparent readiness.**
   `unknown_occupancy_unavailable_host_and_missing_auth_are_named_holds_not_readiness`

## Proof that the preview has no effects

1. **Static surface scan** (inside
   `the_preview_has_no_effects_and_reads_only_the_durable_state_store`): the
   module source must not contain process/network/durable-write tokens
   (`std::process`, `Command`, `std::net`, `TcpStream`, `UnixStream`,
   `std::fs`, `remote::`, `adapters::`, `client::`, `daemon::`, `.spawn(`,
   `start_instance`, `issue_grant`, `record_evidence`, `pause_instance`,
   `resume_instance`, `append_audit`, `rotate_epoch`). Probe P4 shows the
   scan bites.
2. **Behavioural pin**: two previews over a seeded state leave
   `state.summary()` unchanged (no journaling, no epoch rotation) and the
   state database file sha256 byte-identical — the preview's only read is
   the existing `State::list_instances` read API.
3. **Rendered boundary statement**: every preview carries
   `boundaries {mutates:false, spawns:false, grants:false, persists:false,
   resumes:false}` plus the no-effects statement; the rendered document
   contains no spawn, grant, unpause or write surface.

## Not proven / deliberately out of this slice

- **No CLI/RPC surface is wired here.** The brief gated `src/commands.rs` to
  genuinely required changes; none was required, and `src/plan.rs` is
  byte-unchanged, so the merged `hf-plan/v1` renderer and the lane CLI keep
  their contracts. Exposing the preview over the CLI is the follow-up
  surface slice (the same split #83 used for the read model).
- **Occupancy / host availability / credential attestations are
  caller-attested** (the same client-attestation boundary the daemon's
  admission bundle uses). Live host-proof freshness stays a run-time
  admission input; the preview never re-measures, because probing would be
  an effect.
- **Titles are rendered as presented** (display text; never identity, never
  digest-bound). This matches the merged `lane preview` plan, which renders
  its presented `reason` text as-is; the shared redaction pass stays at the
  adapter boundary.
- The aggregate ran exactly once at the candidate head; the documentation-
  only report commit was not re-gated (one-run rule), but the tracked-tree
  scanners were re-run at the delivered head (below).
