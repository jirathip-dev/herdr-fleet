  - Official adapter metadata: Hermes (`hermes`), Claude Code (`claude`), Codex (`codex`) with declared version ranges (compatibility.md rows, measured 2026-09-06) and the full closed harness capability set.
  - Declarative generic `argv` profiles: validated explicit capability subsets, bare executable names resolved through the allowlisted PATH (the verified absolute identity is spawned), explicit per-op static argv prefixes.
  - Typed operations: `start` (session binding), `prompt` (payload as one final data element — never interpolated, AC5), `observe`/`interrupt`/`outcome`/`identity` (workspace session protocol via the workspace executable; v1 candidate invocation rows, real parity [awaiting-evidence]).
  - Version/presence probing (`<exe> --version`, range gate), hermetic executable resolution from the allowlisted environment map, per-op deadlines, output cap + one redaction pass at the boundary, typed exits (`hf-error/v1`-shaped codes: `unknown.harness`, `unknown.capability`, `refusal.unavailable.harness`, `refusal.credentials`, `refusal.malformed.output`, `refusal.stale.identity`, `refusal.identity.incomplete`, `refusal.request.malformed`, `adapter.timeout`, `adapter.process_death`, `adapter.exit`).
  - Stable agent identity (AC3): `AgentIdentity` binds herdr workspace session + stable terminal/native-session identity + generation; pane labels are not part of the type; incomplete binds and stale read-backs are typed refusals.
  - Outcomes render as validated `hf-outcome/v1` documents (`succeeded`/`failed`/`ambiguous`/`refused`).
- `tests/harness_adapters.rs` (new) — fake-executable contract tests: every official adapter plus the argv adapter is driven by fake `hermes`/`claude`/`codex`/`hf-argv`/`herdr` executables created in per-test temp dirs and resolved only through the allowlisted PATH, so no real harness can ever be reached and public CI needs no credentials (AC7).

- No changes to `justfile`, workflows, `deny.toml`, `rust-toolchain.toml`, `Cargo.toml`/`Cargo.lock` (zero new dependencies), config schema, daemon RPC set, or fixtures (oracle stays 62 expectations).

## Acceptance-criteria mapping (AC -> test/file)

- AC1 (same core workflow/plan fixtures pass against fake implementations of every adapter contract): `tests/harness_adapters.rs::same_plan_fixture_passes_against_fake_implementations_of_every_adapter_contract` — the canonical `plan.valid.json` (and `workflow.doctrine.json`, validated as closed families first) drives the same typed scenario (start -> prompt -> outcome -> identity derived from plan step kinds, payload derived from the plan's issue binding) against fake hermes, fake claude-code, fake codex, and the argv fake; every implementation reaches the same all-`succeeded` status sequence and every step produces a validated `hf-outcome/v1` doc.
- AC2 (per-official exact-version contract tests: success, missing executable/auth, unsupported capability, timeout, cancellation, malformed output, stale identity, process death): `official_exact_version_probes_accept_declared_current_and_refuse_below_minimum`, `success_prompt_delivers_the_payload_as_data_and_returns_the_transcript`, `missing_executable_is_a_typed_unavailable_refusal_and_independent_ops_survive` (missing executable), `auth_failure_is_a_typed_credentials_refusal` (auth), `unsupported_capability_is_a_typed_refusal_at_the_named_boundary` (unsupported capability), `hanging_prompt_is_deadline_cancelled_and_ambiguous` (timeout), `interrupt_operation_is_accepted_and_terminal_state_is_observable` (cancellation), `malformed_workspace_output_is_a_typed_malformed_refusal` (malformed output), `identity_read_back_matches_the_bound_triple_and_stale_read_backs_are_refused` (stale identity), `process_death_is_a_typed_ambiguous_outcome` (process death) — each loops over all three official adapters with fake executables pinned to the declared current version.
- AC3 (stable agent identity binds Herdr session + terminal/native-session identity + generation; pane labels alone insufficient): `adapters.rs::bind_identity_requires_all_three_parts_and_labels_cannot_substitute` (incomplete binds refused with `refusal.identity.incomplete`; the identity type has exactly the three parts and no label constructor), integration `identity_read_back_matches_the_bound_triple_and_stale_read_backs_are_refused` (workspace read-back mismatch on generation or terminal session -> `refusal.stale.identity`).
- AC4 (unknown/unavailable harnesses fail clearly without breaking independent read-only operations): `unknown_harness_kind_fails_typed_and_independent_probes_keep_working` + `missing_executable_is_a_typed_unavailable_refusal_and_independent_ops_survive` (per-surface degradation: a missing harness executable leaves workspace/observe ops and other profiles working) + `config_profiles_parse_official_kinds_and_refuse_unknown_ones` (`unknown.harness` typed refusal).
- AC5 (prompts/untrusted text transported as data; no shell/string interpolation; cannot alter argv or policy): `hostile_payload_text_is_data_and_cannot_alter_argv_or_environment` (metacharacter payload arrives verbatim as one argv element, the fake pins the documented argv shape, no injection side effect) + `success_prompt...` exact round-trip; data-last rule enforced in `execute_op`.
- AC6 (clean-host authenticated smokes on maintainer hosts; redacted exact-version evidence only): documented below under "Clean-host authenticated smokes (human gate — NOT run on this lane)". No credentials in this repo; compatibility.md carries the measured version rows only.
- AC7 (public CI / fork PRs need no harness credentials): all contract tests use fake executables on a temp allowlisted PATH; `hostile_payload...` asserts the child sees only the allowlisted env; the full `just ci` gate ran with zero credentials.
- AC8 (no token storage, no arbitrary environment reads, no raw prompt/transcript persistence): adapters contain no filesystem writes and never call `std::env` (environment arrives only as the allowlisted map; `process.rs` `env_clear` is the only channel); transcripts are captured in memory, capped and redacted; tests assert host variables do not reach children.
- AC9 (no plugin/MCP/hosted service/Corral dependency/product-specific core branch): no `Cargo.toml`/`Cargo.lock` change (zero new dependencies), no new families/fixtures, daemon RPC set untouched, `no_network_surface` still green; official adapters are adapter-layer metadata only (ADR-0003), never core branching inputs.
