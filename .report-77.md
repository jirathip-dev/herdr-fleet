## What landed

One bounded target-profile binding added to replacement PLANNING and one
verification of what the successor ACTUALLY bound, through the SAME
adapter and admission paths as #73–#76. No new store beyond one additive
table, no scheduler, no automatic rotation trigger, no whole-fleet restart,
no new dependency, and none of the excluded behaviors (no live in-place
provider switching, no profile editing, no benchmark/availability service,
no automatic fallback-policy expansion).

- `src/config.rs` — the `hf-profile-binding/v1` plan document and its
  derivation from supported profile configuration: `ProfileBinding`
  (`material`/`revision_of`/`to_doc`/`to_canonical_text`/`from_config`/
  `from_doc`), `secret_digest` (sha256 over a domain-separated preimage, or
  `unset`), `credential_environment`/`credential_presence` (NAMES only),
  and the new optional harness keys `fallback` (authorized
  `"provider/model"` bare-token pairs), `secret_env` (credential env names,
  each already in `env_allow`), `limits` (metadata overrides: bounded
  string/integer scalars) and `binding_introspection`. The revision is the
  sha256 over the canonical material, so a configuration OR credential
  change produces a new revision. Unit tests cover the preview, the
  revision sensitivity of every axis, the credential-digest semantics, the
  no-disclosure property and the validated decoder (revision recompute,
  closed key set, bounded shapes).
- `src/schema.rs` + `scripts/check-contract-fixtures.py` +
  `schemas/fixtures/config/config.valid.toml` +
  `scripts/test-check-contract-fixtures.py` — the `hf-config/v1` shape
  rules for the new harness keys, mirrored in the independent fixture
  oracle, with three new tamper cases (non-boolean introspection flag,
  non-scalar limit value, non-array fallback list).
- `src/commands.rs` — `config show --json` previews the exact plan (the
  full `hf-profile-binding/v1` document incl. revision and credential
  digests) plus the declared credential NAMES as
  `declared`/`present`/`missing`; the human output names the revision and
  the intended pair. This is the preview surface the human reviews before

- `src/state.rs` — additive `m0008` (`lane_replacement_profiles`, one bound

## Per-AC statement (issue #77 acceptance list)

1. **Replacement requested under an explicit profile-configuration
   revision; a changed relevant configuration invalidates the
   authorization or requires a newly reviewed plan.**
   `reviewed_profile_plan_binds_the_replacement_and_verifies_the_actual_binding`
   (the real CLI `config show --json` revision is the revision the request
   binds; the durable record and status echo it) and
   `changing_the_configuration_revision_requires_a_newly_reviewed_plan` (a
   self-inconsistent revision refuses `refusal.profile.revision`; a
   malformed plan refuses `refusal.profile.binding`; after editing the
   config the fresh preview has a different revision and the start under it
   refuses `refusal.profile.revision` with NOTHING spawned and the record
   still `retired`; a start that drops the plan refuses
   `refusal.profile.binding`; the reviewed plan still starts). The
   state-layer test `lane_replacement_profile_plan_is_fenced_at_the_start`
   pins the same fence at the state boundary (changed revision ⇒
   `refusal.profile.revision`, material mismatch/missing plan ⇒
   `refusal.profile.binding`, record unchanged).
2. **The source session is untouched until normal quiescence/retirement;
   dirty work, role, issue, exact-head review state and human gates
   survive the model change.**
   `reviewed_profile_plan_binds_the_replacement_and_verifies_the_actual_binding`
   asserts the profile-bound request is a durable record that invokes
   NOTHING (zero workspace rows) and that the whole
   checkpoint/retire/start/adopt chain still compares the recorded
   snapshot (role/task/worktree/branch/head/base/dirty/untracked/report
   scalars plus gates/children) and adopts only on an unchanged re-query —
   the #74/#75/#76 source-untouched machinery is unchanged and its suites
   (`checkpoint`, `retirement`, `start_adopt`) stay green.
3. **Record the intended provider/model and the actual binding from
   authoritative adapter evidence; an unknown actual binding stays
   unknown/unverified, never a copy of the requested configuration.**
   `reviewed_profile_plan_binds_the_replacement_and_verifies_the_actual_binding`

   `unknown_actual_binding_stays_unknown_and_is_never_copied` (no
   introspection evidence in the read-back ⇒ `status: unknown`,

   `authorized_fallback_is_accepted_and_reported_distinctly` (the

## Not proven / caveats

- **The daemon binds and enforces the PRESENTED plan; it does not read
  config files.** Computing the plan from the host configuration and
  environment is the preview's job (`config show --json`, unit-tested in
  `src/config.rs`); the integration test drives the REAL CLI preview into
  the request, but the daemon trusts the presented material after its own
  validation (revision recompute over the presented bytes, closed key set,
  bounded shapes) — a caller that lies about its own environment can only
  lie consistently with the revision it presents.
- **Credential digests are not verified against live secret material by
  the daemon.** Secrets stay in the harness (trust model T5); the digest
  participates in the revision and is bound to the record. A credential
  rotation invalidates a reviewed plan only through a fresh preview
  (documented in `docs/contracts/spec-config.md`).
- **The successor read-back binding grammar is pinned by fake executables**
  (`tests/profile_binding.rs`, synthetic `example-*` values). Real-world
  Herdr `session show` parity remains [awaiting-evidence] exactly like the
  earlier handoff slices; `binding_introspection` is a declared profile
  property, and a profile that cannot report a binding is recorded `unknown`
  rather than guessed.
- **Hosted CI was not run from this lane**; the local aggregate (`just ci`,
  raw exit 0) plus the three explicit scripts are the gate evidence
  available here.
- **Excluded by the issue and not implemented**: live in-place provider
  switching, editing user profiles, provider benchmark/availability
  service, automatic fallback-policy expansion, fleet-wide replacement,
  watchdog deployment and production activation. Existing paused state is
  untouched.
- The crash-point hooks are honored in debug builds only (release binaries
  ignore `CANTER_CRASH_POINT`), matching the existing #73–#76 pattern.
- Anti-slop tooling does not exist in this repository (it is a
  synergy-apps gate); no anti-slop delta applies.
