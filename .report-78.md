  core: `PlanInput` validation mirroring the daemon's closed rules
  (slug/positive generation/actor/doctrine role/repository-relative

  and its **plan digest** (sha256 over the canonical bytes of exactly the

## Acceptance points (issue #78), each pinned to a test

1. **Help and examples demonstrate preview, explicit authorization/request
   and read-only status for one exact lane; command names documented and
   exercised.** `LANE_USAGE` (documented command names + worked examples)
   is pinned by `commands::tests::lane_invocations_parse_and_validate`
   (help text + parsing/validation); the three commands are exercised
   end-to-end by every `tests/lane_cli.rs` test (e.g.
   `preview_and_status_send_only_read_only_rpcs`,
   `authorization_paths_bind_the_same_plan_digest`,
   `status_reports_phase_bindings_next_action_and_guidance`).
2. **Preview shows source identity, target profile, worktree, effect
   boundaries and retained workers/gates; no mutations from preview/status.**
   `preview_shows_source_profile_worktree_boundaries_and_retained_refs`
   (real daemon: source session/process/role, `--profile` derived plan with
   its revision + provider/model, worktree, `mutates:false` + 7 effect
   boundaries, retained worker/reviewer/pending-gate references from a
   committed checkpoint; the journal seq is unchanged) and
   `preview_and_status_send_only_read_only_rpcs` (recording fake daemon:
   only `lane.replacement.status` / `lane.checkpoint.status` ever issued).
   The in-process guard is pinned by
   `commands::tests::the_read_only_lane_guard_refuses_every_mutating_method`.
3. **Human confirmation and noninteractive explicit authorization bind the
   SAME exact plan digest; blanket `--yes` cannot bypass protected/production
   policy.** `authorization_paths_bind_the_same_plan_digest` (preview digest
   is deterministic; the typed-digest human path and `--confirm-digest` bind
   the identical digest; a wrong digest refuses `refusal.plan.stale` in both
   paths with nothing created) and `blanket_yes_cannot_bypass_the_policy_overlay`
   (`tty`: `--yes` refuses `refusal.confirmation.policy` before any daemon
   call and creates nothing, the digest still authorizes; `deny`: every mode
   refuses `refusal.policy.production`).
4. **Human output and versioned JSON agree on phase, intended/actual model,
   blocker, last verified transition and next supported action; stable
   codes; JSON never prompts and carries no prose noise.**
   `json_mode_never_prompts_and_human_and_json_agree` (JSON with no
   authorization is the typed usage refusal, never a stdin read; `--confirm`
   is refused with `--json`; the human preview carries the same digest,
   source, worktree and intended pair) and
   `status_reports_phase_bindings_next_action_and_guidance` (human and JSON
   agree on phase/outcome/blocker/intended/actual/last transition/next; the
   actual binding stays `unknown` with a null pair — never a copy of the
   intended). `refusals_and_successes_render_identically_in_human_and_json_modes`
   pins success/refusal parity (same phase, same `refusal.replacement.exists`
   code, same exit 4 in both renderings).
5. **While the fleet is PAUSED, status stays useful but request/advance
   cannot resume it; no hidden auto-resume.**
   `paused_fleet_status_stays_useful_and_request_does_not_resume` (a
   durably paused schedule stays paused after `lane request`; `lane status`
   renders phase/next-action; no resume/auto-start/auto-advance text
   anywhere). Interpretation, stated plainly: the product's pause surface is
   the durable schedule row (`schedules.pause`); the CLI has no resume path.
6. **Ambiguous retirement, capacity hold, failed adoption and unknown model
   binding each give actionable guidance using only existing commands.**
   `ambiguous_retirement_is_reported_with_reconciliation_guidance` (a real
   crash-interrupted `lane.retire` parked `ambiguous` by restart
   reconciliation: blocker + the external-reconciliation guidance, naming
   only existing commands) and
   `status_reports_phase_bindings_next_action_and_guidance` (the `retired`
   record gives the capacity-hold guidance naming the admission refusals and
   the bounded retry; the `adopting` record gives the failed-adoption
   guidance and the unknown-binding guidance; every string references only
   existing commands/daemon operations). Guidance strings are also unit-pinned
   by `handoff::tests::ambiguous_and_held_records_give_guided_actions` and
   `handoff::tests::unknown_actual_binding_gives_guidance_and_never_copies_the_intended_pair`.
7. **Socket-backed tests prove preview/read-only behavior, success and
   refusal parity, bounded waiting and stale plan rejection; operator docs
   updated honestly.** `preview_and_status_send_only_read_only_rpcs` (wire
   evidence), `refusals_and_successes_render_identically_in_human_and_json_modes`
   (parity), `a_hung_daemon_is_a_bounded_typed_refusal` (a socket that never

8. **Reuse the status/format conventions from #55/#59/#60/#62 rather than
