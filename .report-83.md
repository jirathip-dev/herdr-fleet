## Provenance — what #59/#60/#64 actually provide today

Checked against the current tree before implementing (the issue wins over
the brief):

- **#59 (single-instance status RPC) is NOT implemented.** The closed RPC
  set (29 methods, `src/schema.rs::RPC_METHODS`) has no instance-detail
  method and `daemon::method_status` returns daemon/state aggregate facts,
  not a work-item explanation. The durable *reads* it needs already exist
  and are reused: `State::instance_by_id`, `State::list_instances`,
  `State::evidence_for_instance`, `State::summary`.
- **#60 (CLI instance view) is NOT implemented** and depends on #59. No
  `status`/instance CLI path was added by this slice (CLI-parity wiring is
  a follow-up slice, not part of this read contract).
- **#64 (GitHub work-item snapshot persistence) is NOT implemented.** No
  work-item table exists (the migration chain ends at m0008 with the
  replacement-profile table). The intake-side facts this slice can join
  are therefore the *recorded* bindings on the run itself: repository
  identity, issue number, and the acceptance revision bound when the run
  started (`instances.issue_revision`).
- **Reused, not duplicated:** the state layer (`state.rs`: instances,
  evidence, epoch/summary), the evidence semantics of the merge gate
  (latest row, `verdict == pass` and all checks `passed`,
  `src/mutation.rs::check_merge_evidence`), the shared conservative
  redaction boundary (`src/redact.rs`), canonical serialization/digests
  (`src/canonical.rs`), the closed-family validator pattern and the
  fixture corpus machinery (`src/schema.rs`, `schemas/fixtures/`,
  `scripts/check-contract-fixtures.py`).
- Because #64's snapshot store is absent, the read model derives the
  stable local work-item identity from the recorded repository identity +
  issue number instead of inventing a store, and it never claims a remote
  observation it did not make (`source.observed_at` is always `null` on a
  board read). The absent "recorded reason/owner text" is reported as
  `null` (producer gap), exactly as #59's own wording requires.

## Acceptance points, each pinned by a named test

1. **Identities cannot collide; multiple attempts stay separate.**
   `tests/board_read_model.rs::board_rows_keep_runs_separate_and_derive_stable_work_item_identity`
   — two runs of one issue are two rows with the same stable `wi_` id;
   repository/issue differences cannot collide; ids are deterministic.
   Also pinned in the fixture corpus (`board.valid.json` carries two runs
   of one issue).
2. **Row contract + idle/working never implies delivery.**
   `board_rows_expose_the_required_contract_fields` (stage, owner, reason,
   next action, human gate, evidence references, source
   freshness/completeness all present; unrecorded facts are `null`) and
   `board_never_implies_delivery_from_activity_or_reported_status` (exact
   stage/verification per seeded new/running/paused/blocked/human-queue/
   reported-done/evidence-passed/evidence-failed run; only recorded review
   evidence reaches `verified`; a `done` status without evidence is
   `needs_attention` with `verification: none`).
3. **Pagination deterministic and bounded; empty/stale/missing
   source/out-of-order/restart covered.**
   `board_pagination_is_deterministic_bounded_and_restart_stable` (reverse
   insertion order, 3×3 pages with no overlap and no gap, strictly
   increasing key, cap refusal, cursor validation, restart re-read
   equality) and `board_empty_stale_and_missing_source_cases_are_covered`
   (valid empty page; epoch rotation ⇒ `stale` and never `verified`;
   legacy row without bindings ⇒ `partial` + `null` work item; every
   rendered page validated).
4. **GitHub spec and local execution ownership stay separate; no remote
   request per rendered row.**
   `board_page_read_has_no_process_or_remote_surface_per_row` (static
   surface scan over `src/board.rs` for process/network/remote tokens +
   behavioural invariant that no row claims a remote observation; the
   rendered `source.observed_at` is always `null`).
5. **Contract fixtures prove verified differs from reported-done; private/
   credential data redacted; read-only boundaries preserved.**
   `board_contract_fixture_proves_verified_differs_from_reported_done`
   (fixture accepts; the reported-done row and the verified row differ;
   two tampers — verified label, passed claim with no evidence — refuse)
   and `board_redacts_recorded_text_before_it_becomes_a_row` (token
   absent, `[REDACTED]` present, unredacted text refused by the family
   validator) and `board_reads_are_read_only` (state summary and database
   bytes unchanged across repeated page walks; two reads agree on every
   fact). The evidence-reference bound + explicit overflow is pinned by
   `board_evidence_references_are_bounded_with_explicit_overflow`.
6. **Focused regressions + canonical aggregate at the exact candidate
   head; no private identities/credentials in public examples.**
   Gate evidence below; fixtures use `example-org/*` synthetic identities
   only and the scanner/gitleaks steps are green at the committed head.

## Not proven / deliberately out of this slice

- **No RPC or CLI surface is wired here.** Exposing the page over the
  daemon request path (`daemon.rs` request handling) or the CLI
  (`commands.rs`) is out of this slice's file ownership; the contract,
  validator, fixtures, and read API are the deliverable the surface
  slices consume.
- **`owner` and `reason` are always `null`.** The durable store records
  counters/flags, not owner or reason text; per the "missing fields stay
  unknown" rule they are rendered `null` rather than inferred. The
  redaction boundary is therefore exercised through the recorded
  `reviewer` identity (the only recorded free text this slice exposes).
- **"No remote per row" is proven by a static surface scan plus the
  no-observation invariant**, not by intercepting a live subprocess: the
  reader's only inputs are the state handle and the query, and the probe
  shows that adding a spawn site is caught.
- **The `done` status is seeded in tests by direct SQL** because no public
  API writes it yet in the current tree (m0001 declares the status
  vocabulary; a later slice owns the transition). The read model reports
  it truthfully without claiming delivery.
- The aggregate ran exactly once at the candidate head; the
  documentation-only report commit was not re-gated (per the one-run
  rule), but the tracked-tree scanners were re-run at the delivered head
  as part of closeout.
